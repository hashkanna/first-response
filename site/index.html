02 / How it works

A conversation up front.
An investigation in parallel.

Full architecture ↗

Gemini Live carries the conversation. A FastAPI hub gives it incident facts while a separate Pydantic AI agent investigates and generates repairs.

  1. 01

    Observe the failure

    Real checkout probes, a stack trace, the deploy diff, and numbered source ground the diagnosis.

    Python shop · Pydantic AI
  2. 02

    Generate three edits

    Gemini proposes distinct, bounded source edits. Each is tied to the exact source snapshot.

    Gemini · validated output
  3. 03

    Test independently

    Each candidate runs in its own network-disabled sandbox against a reproduction and 24 unchanged regressions.

    Modal · parallel sandboxes
  4. 04

    Approve & recover

    The operator confirms a verified repair. Fresh Modal tests and checkout probes check recovery before a patch is ready to download.

    Human approval · fresh proof
Gemini Live

Ask about the cause or the failed candidate. Interrupt and keep talking. In the tested stream, a spoken apply request opens patch review; a typed command or button confirms the repair.

03 / Built to be inspected

Two real faults.
One complete repair loop.

The second incident removes a guard for an optional coupon. Gemini generated three distinct repairs; all three passed. Both incidents reached verified recovery through the same workflow.

This prototype covers two controlled faults in a toy shop. Generated edits are limited to one existing assignment line, tests remain independent, and generated code executes only in Modal. The hosted page is a demo showcase; run the application from the repository.

Voice checks used synthesized microphone input with the real Gemini relay. Human headset rehearsal remains separate. Timing is a single observed run, not a performance guarantee.
